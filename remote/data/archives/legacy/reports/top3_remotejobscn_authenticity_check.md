## 单岗位判断

## 1. 远程兼职 — 云基础设施 & Python 开发工程师

**真实性判断：中等偏低，建议先沟通，不建议先投入工作。**

支持真实的证据：

- JD 描述具体到 `多云基础设施`、`FinOps`、`多云环境日常巡检`、`自动化脚本维护`、`阿里云`。
- 薪资 `¥3000-5000/月` 对每周 `15-20 小时` 的兼职是合理区间，不像虚高诈骗。
- 客户行业描述为 `大型跨国企业（消费品、农业科技等领域）`，符合技术咨询公司可能承接的项目类型。

降低可信度的证据：

- 没有最终公司名，只写“我是一家小型技术咨询公司的负责人，base 国内”。
- 没有招聘方官网、工商信息、邮箱域名。
- 职责被 RemoteJobsCN 截断，只看到一条核心职责。
- Eleduck 原帖无法匿名访问评论和发帖者信息。

必须核验：

1. 最终付款主体是谁？
2. 是否签合同？
3. 是否月结？是否先干活后付款？
4. 生产权限怎么给？是否需要接触客户敏感数据？
5. 是否接受先做一个小任务并即时结算？

## 2. Python开发工程师(agent)

**真实性判断：中等，方向可信，但雇主不可验证。**

支持真实的证据：

- JD 技术内容匹配真实后端需求：`AI电商agent平台后端开发`、`API接口设计`、`系统架构优化`、`产品需求落地`。
- 招聘人数 `2`，薪资方式为 `按项目功能报价` 或 `固定按月支付`，符合早期外包/兼职开发需求。
- 外部搜索找到过历史相似岗位，包含更完整技术要求：`Django/FastAPI/Flask`、`RESTful API`、`MySQL`、`Redis`、`定时任务`、`消息队列`、`接口限流`。

降低可信度的证据：

- 公司名缺失，只写 `Eleduck Hiring`。
- 薪资没有金额和币种。
- `微信面试` + `按项目功能报价`，如果不签合同，后续扯皮风险高。
- 历史相似版本可能说明需求长期招不到人、反复转发，需确认是否同一项目。

必须核验：

1. 是个人项目、公司项目还是外包转包？
2. 代码库是否已存在？
3. 项目目前阶段：Demo、MVP、线上维护还是重构？
4. 付款方式：按功能点、按周、按月、里程碑？
5. 是否允许先签一个明确小里程碑？

## 3. Python开发工程师

**真实性判断：中等，技术需求合理，但项目边界和付款风险较高。**

支持真实的证据：

- JD 具体写了 `ERP系统日常维护`、`功能迭代`、`问题排查`、`爬虫程序改造`、`稳定性调试`。
- 要求 `2 年以上 Python 开发经验`，和岗位难度基本匹配。
- 招聘人数 `1`，按项目功能报价，符合小型系统维护/爬虫优化外包需求。

降低可信度的证据：

- 没有公司名。
- 没有说明 ERP 系统技术栈、数据库、部署方式。
- 爬虫项目可能涉及反爬、账号、合规风险。
- 只有 `微信面试`，没有合同和验收机制信息。

必须核验：

1. ERP 系统使用什么框架、数据库、部署环境？
2. 爬虫目标站是否有授权？是否涉及绕过登录、验证码、付费内容？
3. 原系统是否有文档、测试环境、备份？
4. 报价是否按功能拆分？Bug 修复是否额外计费？
5. 是否可以先做诊断报告，诊断也收费？

## 总体建议

不要把这三个岗位当成“正规全职 offer”看待，要按“远程兼职/外包项目线索”处理。

安全投递策略：

1. 可以先联系，但不要先交任何费用。
2. 不接受押金、设备费、资料费、培训费。
3. 不接受“先完整开发后付款”。
4. 第一次合作只接小任务，最好 1-3 天内能验收。
5. 每个任务先写清楚交付物、验收标准、付款节点。
6. 生产系统权限必须最小化，不要接收不明来源账号池、绕验证码、爬付费内容等任务。

   ERP + 爬虫维护需求最朴素，最像真实外包任务，但要控制付款风险。

2. `远程兼职 — 云基础设施 & Python 开发工程师`  
   薪资和时间合理，需求方向合理，但公司主体太模糊。

3. `Python开发工程师(agent)`  
   技术方向最适合长期路线，但公司主体、项目阶段、报价边界最需要确认。
